## 页面 4: 投机解码 (Speculative Decoding)

* **核心痛点**：使用大型语言模型（LM）进行自回归生成极其缓慢。
* **直觉认知**：并非所有的 Token 生成难度都是均等的！
* **核心思想**：利用小型语言模型（草稿模型 Draft model）的生成来辅助大型语言模型（目标模型 Target model）的生成。
* Google Research (Leviathan et al., Nov 2022) 和 DeepMind (Chen et al., Feb 2023) 独立且同时提出了这一思想。

---

## 页面 5: 投机解码的加速原理

* 投机解码允许大模型在一个前向传播步（Forward Pass）中验证多个 Token，如果小模型草稿生成的候选被大模型接受，就能实现多倍的生成速度提升。

> **[学习注释：验证阶段“一次前向传播算出多个位置 Softmax”的张量并行本质与误区澄清]**
> * **关键误区澄清**：初学者常产生认知偏差，以为 Decoder-only Transformer 每次前向传播只能计算并输出一个 Token 的 Softmax 概率向量。**事实上这是错误的。** Transformer 最后一层输出的特征矩阵形状为 $[T, d]$（$T$ 为输入序列长度），经 LM Head 映射后输出的 Logits 和 Softmax 矩阵天然是 $[T, Vocab\_Size]$ 的二维张量。它包含了这 $T$ 个位置上各自预测下一个词的条件概率分布。普通推理中因采用 `logits[-1, :]` 切片丢弃了前 $T-1$ 行，才让人误以为一次只能算一词。
> * **投机解码的加速秘密（并行验证的本质）**：
>   * 在自回归生成中，由于后续 Token 尚未生成，我们被迫串行运行 $k$ 次前向传播（每次搬运几百亿参数，构成严重的物理访存带宽瓶颈）；
>   * 投机解码中，小草稿模型先行串行生成了 $k$ 个候选 Token。由于**输入序列已知**，大模型便可直接运行类似预训练时的**并行矩阵乘法**。
>   * 配合时间掩码（Causality Mask）的行遮挡，大模型**仅需运行一次（1次）前向传播**，即可瞬间在输出端同时拿到这 $k$ 个不同位置上的条件概率分布 $\mathbf{q}_1 \dots \mathbf{q}_k$。这就是课件中“在一次计算中并行验证这一串 Token”的硬件物理本源。

## 页面 6: 投机解码流程演练：草稿模型生成与验证

* 草稿模型（例如 1B 参数）快速预测出接下来的几个 Token。
* 目标模型（例如 100B 参数）在一次计算中并行验证小模型写下的这一串 Token，并输出概率分布进行比对。
* 例如：小模型草稿输出为 `dogs love chasing after cars`
* 比对各自位置的概率比率。

---

## 页面 7: 投机解码流程演练：第一步验证与接收

* 如果目标模型在该位置的接收条件成立（比对两者的采样概率比率），则接受当前 Token。
* 验证生成的第一步：接收 `dogs`。

> **[学习注释：接收判定时的概率表征本质]**
> * **重要说明**：大模型在决定是否接受小模型的候选词时，所使用的概率比率 $q(x)$，**就是大模型自己跑完推理、并已经应用了它自身当前设定的采样方法（如 Temperature 缩放、Top-p 截断、重复惩罚等）所算出来的最终那个 Softmax 采样概率分布**。因此，采样策略的变化已完全内化在输入概率分布 $\mathbf{q}$ 和 $\mathbf{p}$ 的数值形状上，投机算法本身的代码无需做任何适配改动即可严格复刻。

## 页面 9: 投机解码流程演练：采样比率校准

* 当在某一步目标模型拒绝了草稿模型的 Token 时，算法会根据目标模型在此处的真实条件分布重新采样生成一个修正 Token，并截断这一轮后续的投机路径。

## 页面 10: 投机采样算法分类讨论 (三种情况)

* 算法详细定义了如何严格校准小模型采样概率 $p_i$ 与大模型目标概率 $q_i$，使得整体采样效果数学上等价于直接从昂贵的目标大模型中进行采样。
* 形式化数学证明详见 (Chen et al., 2023) 的附录 I。

> **[学习注释：投机接收准则与重采样关键公式]**
> * **投机接受判定（Rejection Sampling）**：
>   设小模型生成候选词为 $x^*$，在当前上下文下，小模型与大模型的采样概率分布中该词概率分别为 $p(x^*)$ 与 $q(x^*)$。系统限制均匀分布随机数 $r \sim U(0, 1)$ 进行判定：
>   * 若 $q(x^*) \ge p(x^*)$，**100% 接受** $x^*$；
>   * 若 $q(x^*) < p(x^*)$，以概率 **$\frac{q(x^*)}{p(x^*)}$ 接受** $x^*$（即 $r < \frac{q(x^*)}{p(x^*)}$ 时接受，否则拒绝）。
> * **被拒绝后的残差重采样（Residual Re-sampling）**：
>   一旦某一步候选词被拒绝，此步后的投机全部截断作废。大模型在此位置从以下**残差分布**中重新采样生成一个修正 Token：
>   $$q'_{\text{new}}(x) = \frac{\max\big(0, q(x) - p(x)\big)}{\sum_{x'} \max\big(0, q(x') - p(x')\big)}$$
> * **数学等价性**：该公式能严格确保大模型在每一时间步输出任何词 $x$ 的综合边缘概率 $P(X=x) \equiv q(x)$。如在 Greedy 模式下，公式将自回归地退化为 `if (draft == target) accept else reject` 的布尔硬匹配判断。

## 页面 11: 投机解码是一种拒绝采样 (Rejection Sampling) 机制

* **本质**：从一个容易采样的分布 $p$（小 LM）中采样，并基于条件拒绝率，来间接实现了从更为复杂的分布 $q$（大 LM）中采样。
* 实证数据：以 60M 参数的 T5-small 作为草稿模型，11B 参数的 T5-XXL 作为目标模型，可以在保证**输出完全一致**的前提下，获得 2 到 3 倍的推理加速！

## 页面 12: 动态投机解码与通用投机解码

* **动态投机解码 (Dynamic speculative decoding)**：
  * 在每次迭代中自适应调整“前瞻（Lookahead）”大小（即候选 Token 的数量）。使用轻量级分类器或置信度阈值实时决定草稿模型应当继续 drafting 还是切换到目标模型进行验证。
* **通用投机解码 (Universal speculative decoding)**：
  * 原始投机解码要求草稿模型与目标模型具有完全相同的 Tokenizer。
  * 通用投机解码通过引入重编码（Re-encoding）和对齐技术，支持具有异构分词器（Heterogeneous tokenization）的两个模型进行投机协作。

## 页面 14: EAGLE-3 算法原理与特征级外推

* EAGLE 系列的核心思想：
  * **Eagle-1**：让草稿模型窥探目标模型的“内心想法”，通过融入目标模型在前一步计算得到的隐层隐表示来进行特征级别的投机（Feature-level speculation）。
  * **Eagle-2**：引入感知上下文的动态草稿树结构 (Dynamic draft trees)。
  * **Eagle-3**：在不同层之间进行“特征融合 (fused features)”。

> **[学习注释：EAGLE 1-3 架构演进与做法精炼总结]**
> * **EAGLE-1 (特征外推)**：不使用独立小模型，而是引入 1 层极轻量的 Predictor Head。它直接以大模型最后一层输出的高维隐状态（Hidden States）为输入，在**高维隐层特征空间**自回归预测下一步特征，再投影为 Token 候选，显著提升了投机接受率。
> * **EAGLE-2 (动态草稿树)**：根据中间预测的条件熵大小动态决定分叉结构（熵高则分叉多路径，熵低则单链深探），形成草稿树。大模型通过 Tree Attention 仅需 **1 次前向**并行校验多条路径。
> * **EAGLE-3 (跨层多特征融合)**：级联融合大模型的中间层与输出层特征输入给 Head，补充了外推中的信息量，解决了长路径特征消散问题，极大地提升了长距离投机准确度。

## 页面 16: 后缀解码 (Suffix Decoding) 算法 (Oliaro et al., 2025)

后缀解码摒弃了需要训练小草稿模型的做法，转而利用后缀树数据结构来缓存和匹配输入上下文及历史生成文本中重复出现的模式，实现超高速的无模型投机。

> **[学习注释：后缀解码 (Suffix Decoding) 底层机制与后缀树数据结构剖析]**
> * **核心思想（无模型，零训练）**：在代码、SQL、RAG等结构化任务中，大模型生成的文本包含极高频的字面重复（Repetitive Patterns）。算法完全摒弃神经网络小模型，直接利用 CPU 端的高效字符串匹配检索历史生成，零显存消耗，草稿提取只需十几微秒。
> * **为什么使用后缀树而不是固定 n-gram 哈希表？**：哈希表要求 Key 长度 $N$ 必须写死，缺乏灵活性。后缀树（压缩字典树）支持**任意长度匹配**与**最长公共子串匹配**，能自适应提取历史中最契合的长上下文，且支持 Ukkonen 算法在 $O(1)$ 均摊复杂度下在线增量动态插入新 Token。
> * **具体记录与查找机制（以 text="dogs love chasing cars" 为例）**：
>   1. **树的记录**：将该历史文本的所有后缀子串（`dogs love chasing cars`、`love chasing cars`、`chasing cars`、`cars`）作为路径插入一棵 Trie 树中。其逻辑结构图如下（终端为文本的起始物理偏移 Index）：
>      ```text
>                     (Root)
>                    /   │   \   \
>                dogs  love chasing cars
>                 /      │      │     │
>               love  chasing  cars  [Index 4]
>                /       │      │
>             chasing   cars  [Index 3]
>              /         │
>            cars     [Index 2]
>             /
>         [Index 1]
>      ```
>   2. **顺藤摸瓜（Lookahead 投机）**：假设当前步骤最新生成了 `dogs love`，系统将该短语作为 Query 在后缀树上自 Root 向下匹配到 `love` 节点；随后直接沿着树的这根残留枝条继续往下看（Lookahead），取得其连着的 `chasing` 和 `cars` 两个子节点，直接将 `[chasing, cars]` 拷贝作为大模型的投机草稿候选。

## 页面 21: 强化学习术语辨析：在线/离线、同策略 (On-policy) / 异策略 (Off-policy)

* **在线强化学习 (Online RL)**：智能体在训练期间可以直接与环境进行实时交互获取新数据。
* **离线强化学习 (Offline RL)**：训练严格限定在预先记录好的静态数据集上（人类日志或旧版智能体数据），智能体无法进行任何自主探索。
* **同策略 (On-Policy RL)**：用于训练模型的数据必须**完全由当前正在更新的最新策略**实时生成。一旦策略更新，旧数据即被视为过期失效并丢弃。代表算法：REINFORCE, PPO, GRPO。
* **异策略 (Off-Policy RL)**：模型可以利用 any 策略（旧版策略、完全不同的其他模型甚至人类）生成的数据进行学习。利用经验回放池（Replay Buffer）存储历史体验以进行重复训练。代表算法：DQN。

> **[学习注释：有监督学习、离线强化学习、在线强化学习的本质差异辨析]**
> * **有监督学习 (如 SFT / 行为克隆)**：
>   * **数据特征**：状态 $\to$ 唯一确定标签（Golden Label）。
>   * **学习本质**：纯粹的模仿（Imitation）。模型尝试拟合该标签，上限被数据集平均水平卡死，且无法处理数据集中的错误噪声。
> * **离线强化学习 (Offline RL / 如 DPO、CQL)**：
>   * **数据特征**：状态 $\to$ 动作 + 静态对应的 Reward（如偏好对数几率比值惩罚）。
>   * **学习本质**：**价值推演与超越**。不允许智能体做新动作与环境实时交互，只能在死的静态数据中推演最佳决策。通过 Reward 差异拉高好动作概率并主动压低坏动作概率，具备超越数据集上限的能力。
> * **在线强化学习 (Online RL / 如 PPO、GRPO)**：
>   * **数据特征**：状态 $\to$ 智能体自主探索动作 $\to$ 环境（模型或客观规则）实时计算生成新的 Reward。
>   * **学习本质**：实时的交互探索与动态反馈。能够发掘全新的决策状态，但计算开销巨大。

---

## 页面 22: 同策略与异策略强化学习的交叉组合

* **在线异策略 (Online Off-Policy) 组合**：极其常见。智能体与模拟器实时交互（Online），但将所有数据写入 Replay Buffer，后续以异步异策略形式从中学习（如 DQN）。
* 异步大模型强化学习：策略更新存在延迟。
* ⚠️ **离线同策略 (Offline On-Policy)**：在逻辑上几乎不存在（除非强行泛化其定义），因为离线数据无法保持与实时变动的策略高度同步。

## 页面 23: 异步 RLHF 机制 (Noukhovitch et al., 2024)

* 传统的 RLHF 是同步的，由于训练步与生成步耗时差异大，会导致 GPU 吞吐量遭遇严重浪费（生成时训练 GPU 闲置，训练时生成 GPU 闲置）。
* 异步 RLHF 将生成与训练流水线化，从而实现计算资源的极限压榨。

> **[学习注释：同步 RLHF 痛点与异步 RLHF 机制及副作用深度解析]**
> * **角色定义 (分布式 RL 节点工作分工)**：
>   * **Actor (生成节点)**：加载当前模型参数，通过自回归解码（Autoregressive decoding）串行生成文本数据（Rollout），为训练提供新鲜样本。通常属于访存受限型计算。
>   * **Learner (训练节点)**：拉取 Actor 采集的数据，并行运行前向与反向传播计算梯度（Train），计算并更新模型参数。通常属于计算受限型计算。
> * **一、 同步 RLHF 的痛点**：
>   * 串行阻塞瓶颈：系统存在强阻塞式同步屏障（Rollout $\to$ Train $\to$ Rollout）。因自回归生成（Actor）与梯度训练（Learner）的计算特征与耗时差异极大，导致两组 GPU 节点交替处于完全闲置（Idle）状态，硬件吞吐量遭遇严重浪费。
> * **二、 异步 RLHF 的概念与不同点**：
>   * 核心概念：将自回归生成与梯度优化彻底解耦为两个**完全并行的独立异步流水线**，数据和权重通过 Replay Buffer 异步非阻塞中转。
>   * 与同步的不同：生成节点（Actor）与训练节点（Learner）不间断运行，不需要互相等待。Actor 随时把产生的数据丢入 Buffer，Learner 随时从中拉取数据更新参数，硬件利用率逼近 100%。
> * **三、 异步 RLHF 的系统副作用**：
>   * **异策略漂移 (Off-policy drift)**：由于生成极慢而训练极快，当 Actor 生成完序列时，目标模型参数已在 Learner 端被迭代更新了多次，导致“生成数据的行为策略”与“当前优化的目标策略”发生版本偏移。
>   * **混合策略序列 (in-flight updates 副作用)**：当生成长句子中途执行“飞行中显存权重热加载”时，同一句回答的前后不同片段会被不同的策略版本拼凑生成，导致严重的条件概率分布混乱，Learner 端必须设计复杂的偏置修正（如重要性采样）才能收敛。

---

## 页面 24: PipelineRL 算法：飞行中动态权重更新 (Piché et al., 2025)

* **飞行中权重更新 (in-flight weight updates)**：
  生成引擎在生成长文本的过程中，实时接收来自训练集群发来的新模型权重 —— 短暂暂停当前 Token 生成，加载最新权重，然后继续接力生成尚未完成的序列。
  这会导致“混合策略序列”的产生：同一句回答中，前一部分 Token 由旧策略生成，后一部分 Token 则由新策略生成。

---

## 页面 25: 实践中导致“异策略漂移 (Off-policy drift)”的根源

为何在强化学习训练大模型时，同策略数据很容易变质为“过期的”异策略数据？
* 刻意设计的异步 RL 框架。
* 每个 batch 进行多次梯度更新步骤。
* 维护了较大的 Replay Buffers。
* **物理集群的分离**：生成任务（推理优化）与梯度计算任务（训练优化）在物理上部署在不同的 GPU 集群中。在集群之间传输模型参数引入了时间延迟，导致生成集群使用的模型权重总是落后于最新的训练权重。

---

## 页面 26: 异策略漂移带来的危害与常用的工程缓解策略

* **危害**：偏差的梯度估计、重要性采样权重爆炸（Importance weight explosion）、加剧奖励黑客（Reward Hacking）现象。
* **缓解策略**：
  * PPO 算法中引入比率截断（Clipping）。
  * 引入针对参考模型的 KL 散度惩罚。
  * 转向使用不需要价值网络/优势函数估计的轻量化算法（如 GRPO, REINFORCE），以此缩短异策略漂移的时间窗口。
  * 限制单批数据的更新 Epoch 数。
  * 使用 SGLang / vLLM 的连续批处理（Continuous batching）和权重流式传输。
  * 使用 PipelineRL 带来的飞行中权重实时载入。

## 页面 28: 同策略蒸馏 (On-policy Distillation) 机制

* 由 (Gu et al, 2023) 和 (Agarwal et al, 2023) 提出，并在 Qwen 3 技术报告和相关技术博客中被广泛采用。
* **传统知识蒸馏**：是**以教师为中心**的（对学生而言是异策略的，学生在教师给出的语境和答案分布下训练）。
* **同策略蒸馏 (Generalized Knowledge Distillation, GKD)**：是**以学生为中心**的（同策略的，学生在自己生成的上下文分布下，比对教师的输出分布）。

> **[学习注释：传统蒸馏与同策略蒸馏的底层对齐机制、做法与痛点对比]**
> * **传统蒸馏与前向 KL 的关系**：
>   * 传统知识蒸馏在每个 Token 处的交叉熵/最大似然损失函数为 $\text{Loss}_{\text{KD}} = \mathbb{E}_{y \sim P}[-\log Q_\theta(y)]$。
>   * **代数等价性证明**：将前向 KL 散度 $D_{KL}(P \parallel Q_\theta)$ 展开：
>     $$D_{KL}(P \parallel Q_\theta) = \sum_{y} P(y) \log \frac{P(y)}{Q_\theta(y)} = \sum_{y} P(y) \log P(y) - \sum_{y} P(y) \log Q_\theta(y)$$
>     其中第一项 $\sum P(y) \log P(y)$ 是仅与教师分布有关的常数（对学生参数 $\theta$ 的导数为 0）；第二项 $-\sum P(y) \log Q_\theta(y)$ 在代数上正是 $\text{Loss}_{\text{KD}}$ 的期望定义式。因此，优化前向 KL 散度与传统监督蒸馏在梯度更新上完全等价。
> * **传统蒸馏的痛点**：
>   * **以教师为中心（异策略）**：学生模型只在教师生成的完美语境下做纯模仿（Imitation）。这导致学生小模型（如 7B）为了强行覆盖教师大模型（如 70B）的所有知识广度，被迫将概率分布摊平（均值寻求 Mean-seeking），结果表现为废话多、不自信，且在自己生成时极易发生逻辑幻觉。
> * **同策略蒸馏 (GKD) 的优点**：
>   * **以学生为中心（同策略）**：小模型通过自主探路（On-policy），将分布收缩聚焦到大模型认可的核心优秀模式（Mode-seeking）上，使得小模型“答得少但答得准”，逻辑扎实且几乎没有多余幻觉。
> * **同策略蒸馏的具体工作流**：
>   1. **学生采样 (Rollout)**：学生模型自回归采样生成一个长序列 $y_1 \dots y_L$。
>   2. **教师并行前传 (Teacher Forward)**：把学生写出的整句一并喂给教师模型，教师在**一次前向计算（并行矩阵乘法）**中跑出这一串 Token 在所有位置的概率分布表 $\mathbf{p}_1 \dots \mathbf{p}_L$。
>   3. **逆向 KL 损失计算**：在每个 Token 位置，将 Loss 定义为**逆向 KL 散度** $D_{KL}(Q \parallel P)$ 并累加。

---

## 页面 29: KL 散度的方向性：前向 KL (Forward KL) 与逆向 KL (Reverse KL)

* **前向 KL 散度 (Forward KL) —— 均值寻求 (Mean-seeking) / 覆盖概率质量**：
  $$D_{KL}(P || Q) = \sum P(x) \log \frac{P(x)}{Q(x)}$$
  * 以真实分布 $P$ 为权重：当 $P$ 有概率质量而 $Q$ 为 0 时给予极大惩罚。
  * 导致 $Q$ 倾向于覆盖 $P$ 的所有模式（可能会高估支撑集，显得中庸平庸）。
  * 常用于变分推理（ELBO）。
* **逆向 KL 散度 (Reverse KL) —— 模式寻求 (Mode-seeking) / 模式塌缩**：
  $$D_{KL}(Q || P) = \sum Q(x) \log \frac{Q(x)}{P(x)}$$
  * 以模型分布 $Q$ 为权重：当 $Q$ 在 $P$ 没有概率质量的地方生成时给予极大惩罚。
  * 导致 $Q$ 倾向于收缩到 $P$ 的某一个代表性模式上（虽然略微窄化，但生成结果非常敏锐且自信）。
  * 在 RLHF 中被广泛使用，KL 惩罚项即是保持当前策略不偏离参考策略的逆向 KL 形式。

> **[学习注释：逆向 KL 散度在同策略蒸馏中的梯度控制机制]**
> * **逆向 KL 蒸馏 Loss 公式**：
>   $$\text{Loss}_{\text{Reverse-KL}}(\theta) = \sum_{t=1}^L \sum_{w \in \text{词表}} Q_\theta(w \mid x_t) \log \frac{Q_\theta(w \mid x_t)}{P(w \mid x_t)}$$
> * **梯度求导拉扯物理本质**：
>   对小模型参数 $\theta$ 求导后，总梯度中包含了关键的对数比值乘子：
>   $$\nabla_\theta \text{Loss}_{\text{Reverse-KL}} = \sum_{t=1}^L \sum_{w} \nabla_\theta Q_\theta(w \mid x_t) \cdot \log \frac{Q_\theta(w \mid x_t)}{P(w \mid x_t)}$$
>   * **自大垃圾 Token 惩罚**：当小模型在某步给词 $w$ 赋予了高概率（$Q_\theta(w)$ 很大，且梯度倾向为正），但老师认为该词概率极低（$P(w) \approx 0$）时，比值 $\frac{Q_\theta(w)}{P(w)}$ 趋于无穷，使得该步的对数乘子 $\log \frac{Q_\theta(w)}{P(w)}$ 变为一个**极大正数**，强行在反传时对 $\theta$ 施加恐怖的下压引力，彻底抹杀这个荒诞的分支。
>   * **为什么必须 On-policy**：如果不用学生自己探路，它就根本不会误入那些“会让学生自大但老师反对”的上下文位置，也就无法触发上述的无穷大梯度惩罚来建立克制力。

## 页面 30: 同策略蒸馏与标准知识蒸馏 (KD) 的 KL 散度对比

* 传统 KD 通常基于 Forward KL 最小化（Off-policy，导致学生被迫去兼容教师的所有概率模式）。
* GKD（同策略蒸馏）通常基于 Reverse KL 最小化（On-policy，学生从自己生成的分布中学习）。

## 页面 32: 逆向 KL 散度与同策略蒸馏对缓解“曝光偏差”的价值

* **打破训练-测试脱节**：在 GKD 中，上下文来自学生模型自身的探索生成。消除了传统的曝光偏差（Exposure Bias）问题 —— 学生能够学会从自己上一步犯下的错误中自我恢复。
* **自信锐利的模式表现**：模式寻求特性使得学生模型在自己最擅长的行为上表现得极其稳定和锐利，而不会含糊不清地去盲目附和教师模型的所有可能输出模式。

## 页面 33: 同策略蒸馏 vs 监督微调 (SFT) vs 强化学习 (RL)

| :--- | :--- | :--- | :--- |
| **监督微调 (SFT)** | 异策略 (Off-policy) | 密集信号（词级交叉熵） | 轻量级资源需求 |

| **同策略蒸馏 (GKD)** | **同策略 (On-policy)** | **密集信号（教师软概率分布）** | **轻量级资源需求** |

* 同策略蒸馏（GKD）可以被视为融合了 SFT 密集监督优势与 RL 同策略探索优势的“两全其美”的对齐手段。

## 页面 34: 领域特定适配中的同策略蒸馏应用

* 这是一个极其炫酷的应用场景：将开源大模型适配到公司内部特定的私有文档库上（可以视为一种中期训练 Mid-training）。
* **潜在风险**：如果直接以幼稚的监督方式在全新 corpus 上进行中期微调，会导致模型此前已经习得的宝贵对齐能力（如极其关键的“指令遵循指令”能力）发生灾难性退化。
* **解法**：在 70% 的领域私有文档中穿插 30% 的基于同策略蒸馏的通用指令对齐训练，能在快速汲取新知识的同时，完全恢复和维持住极佳的指令遵循能力。

## 页面 43: RoPE：旋转位置编码 (Rotary Position Embedding, Su et al., 2021)

* **核心运作机制**：RoPE 仅将旋转变换应用在 Query 向量 $Q$ 和 Key 向量 $K$ 上，**绝不应用于 Value 向量 $V$**！
* 在 $Q$ 和 $K$ 生成后，将其分拆为二维平面上的向量对，乘以一个与位置 index 相关的旋转矩阵。

> **[学习注释：RoPE 旋转矩阵与高维对角块数学形式]**
> * **二维平面旋转公式**：将二维向量在位置 $m$ 处旋转角度 $m\theta$：
>   $$\mathbf{R}_m \mathbf{q} = \begin{pmatrix} \cos m\theta & -\sin m\theta \\ \sin m\theta & \cos m\theta \end{pmatrix} \begin{pmatrix} q_0 \\ q_1 \end{pmatrix}$$
> * **高维正交对角块矩阵形式**：对于 $d$ 维向量，两两分组为 $d/2$ 个独立子空间分别旋转：
>   $$\mathbf{R}^d_m = \text{diag}\left( \mathbf{R}_{m\theta_1}, \ \mathbf{R}_{m\theta_2}, \ \dots, \ \mathbf{R}_{m\theta_{d/2}} \right)$$
>   其中基底角频率设定为 $\theta_i = 10000^{-2(i-1)/d}$。高频维度（左）转速极快感知近邻，低频维度（右）转速极慢感受宏观依赖。

## 页面 47: 为什么 RoPE 能完美保留相对距离信息

* **奇妙的数学特性**：由于 $q^T R_m^T R_n k = q^T R_{n-m} k$，这意味着在计算注意力时，无论 Taylor 和 Swift 位于句首（位置 10 和 11）还是句尾（位置 100 和 101），**只要它们的相对距离（$11-10=1$）是相同的，它们相乘后的旋转夹角就是完全恒等的！** 😍

> **[学习注释：RoPE 保留相对距离的核心正交性质证明]**
> * **保范性（范数不变）**：由于旋转矩阵 $\mathbf{R}_m$ 属于正交矩阵，旋转不改变向量模长（$\|\mathbf{R}_m \mathbf{q}\|_2 \equiv \|\mathbf{q}\|_2$），这保障了大模型多层传播时的梯度计算稳定性。
> * **相对距离消消乐证明**：因为正交矩阵转置等于逆（$\mathbf{R}_m^T = \mathbf{R}_{-m}$），且平面旋转相乘角度相加减：
>   $$\langle f(\mathbf{q}_m, m), \ f(\mathbf{k}_n, n) \rangle = (\mathbf{R}_m \mathbf{q})^T (\mathbf{R}_n \mathbf{k}) = \mathbf{q}^T \mathbf{R}_m^T \mathbf{R}_n \mathbf{k} = \mathbf{q}^T \mathbf{R}_{n-m} \mathbf{k}$$
>   内积结果 $\mathbf{q}^T \mathbf{R}_{n-m} \mathbf{k}$ 仅仅依赖于相对距离 $n-m$（旋转角度差值），从而在乘性点积注意力计算中完美、纯净地保留了相对距离信息。

---

## 页面 48: 传统正弦位置编码与旋转位置编码 (RoPE) 的对比表

| 维度 | 传统正弦位置编码 (Vaswani 2017) | 旋转位置编码 (RoPE, Su et al. 2021) |
| :--- | :--- | :--- |
| **融合方式** | **加性整合**：在第一层 Transformer 之前直接与输入 Token 嵌入相加。 | **乘性整合**：在每一层计算自注意力时，直接应用乘法于 $Q$ 和 $K$。 |
| **模长保存性** | **破坏模长**：会强行拉大或扭曲 Token 向量的范数。 | **范数不变性**：旋转矩阵属于正交矩阵，完全保留了向量的 L2 范数。 |
| **相对距离保留** | 虽在理论上被捕捉，但由于多层非线性变换的加性叠加，相对距离信息到高层已被完全搅浑（Muddled）。 | 旋转夹角完美表达相对距离，在进行 Query-Key 注意力点积时信息依然保持清晰明了。 |
| **长文本外推性** | 外推表现极度糟糕。 | 天然契合各类主流的长上下文扩展技术（如位置插值、YaRN 等）。 |

## 页面 49: 长上下文扩展工程实践 1：位置编码修改 (PI, NTK-aware, YaRN)

RoPE 缩放（Scaling）是目前（2026年）最主流的一族外推方案：
* **线性插值 (Position Interpolation, PI)**：直接对位置索引按比例压缩，使模型看到的相对位置落回训练过的区间内（例如 Meta 用于将 LLaMA 扩展至 32K ）。需要极少量的继续预训练。
* **NTK-aware 插值**：不进行均匀的线性压缩，而是通过调整旋转基底（Base）的频率来处理不同维度的位置信息，更好保留高频位置细节。其“动态 NTK”变体可根据输入长度在推理时自适应调节缩放因子。
* **YaRN**：结合 NTK 缩放、注意力温度校正项以及一个频率淡入函数（对低频部分进行插值，对高频部分进行外推），从而实现极为平滑的上下文拉伸。

## 页面 50: 长上下文扩展工程实践 2：渐进式/分阶段训练

业界通用的上下文扩容训练配方（如 Llama 3.1 等所采用）：
* 从基座模型（如 4K 或 8K 窗口）起步。
* 载入修改后的 RoPE 位置编码。
* **在长文本上进行渐进式中期训练**：按长度阶梯分阶段增加训练上下文长度（如 8K $\to$ 32K $\to$ 64K $\to$ 128K）。仅需投入数十亿级别的 Token（占原预训练算力预算的 0.1% 到 1%）即可高效完成扩容。
* 在长上下文指令微调数据集上进行最后的对齐微调。

## 页面 52: 长上下文扩展工程实践 4：注意力架构优化

* 引入局部滑动窗口注意力（Sliding window attention）与少量全局注意力 Token 的结合（Longformer 风格）。
* 使用 FlashAttention 系列算法将 Attention 的中间激活值显存占用从 $O(n^2)$ 降低到硬件友好的 $O(n)$。

## 页面 57: 测试时计算规模化的具体策略与验证方法 (ORM vs PRM)

* **评测过的测试时计算策略**：
  * **Best-of-N 采样**：独立生成 $N$ 个候选解答，利用验证器挑选出最优解。
  * **加权 Best-of-N**：在计算最优的温度参数下进行采样。
  * **序列级自我修正 (Sequential revisions)**：利用模型自身的反思机制对单一答案进行多轮迭代修改。
  * **PRM 引导的束搜索 (Beam search with PRMs)**：在步骤级别利用过程奖励模型提供分数，剪去低分旁支，保留最优的思考轨迹。
  * **多样性束搜索**：强制模型探索截然不同的解题范式。
* **评测过的验证方法**：
  * **结果监督奖励模型 (ORM)**：仅预测整道题的最终正确性。
  * **过程监督奖励模型 (PRM)**：在每一个逻辑推理步骤上对正确性进行评估打分。
  * **领域特定验证器**：如数学和代码执行器，自动进行对错判断。

## 页面 59: 测试时计算规模化的核心结论与工程实践建议

* 在 MATH-500 测试集上，一个配备了优化测试时计算策略的 14B 小模型，其实际表现媲美或超越了参数量大出 4 倍的常规大模型。
* 在其实验中，计算最优的算力分配建议将几乎等量的 FLOPs 预算分别投入到预训练与推理阶段。
* 在需要自我纠错和深度修正的任务中，序列级自我修正策略展现出极其强悍的 Scaling 效应。
* 在结合束搜索时，过程奖励模型（PRM）的算力利用效率比结果奖励模型（ORM）高出 4 到 8 倍。
* **实用建议**：
  1. 不要盲目上手最大的模型！先尝试用小模型搭配搜索。
  2. 极力投资构建验证器！高质量的奖励模型（尤其是 PRM）是成功扩展推理阶段算力的核心基石。
