## 页面 4: 适配器 (Houlsby et al. 2019)

* 在预训练模型的各层之间插入一个新的函数 $f_{\phi}$ 以适配下游任务 —— 这被称为“适配器 (adapters)”。
* Transformer 层中的适配器由以下部分组成：
  * 前馈下投影 (Feed-forward down-projection)：$W_D \in \mathbb{R}^{k \times d}$
  * 非线性激活函数 (Nonlinearity)
  * 前馈上投影 (Feed-forward up-projection)：$W_U \in \mathbb{R}^{d \times k}$
  * 残差连接 (Residual connection)：$f_{\phi}(\mathbf{x}) = W_U(\sigma(W_D\mathbf{x})) + \mathbf{x}$

## 页面 11: 传统的阅读理解方法

* 基于特征的方法 (Feature-based)：
  * 生成候选答案列表 $(a_1, a_2, \dots, a_M)$
  * 定义特征向量 $\phi(p, q, a_i) \in \mathbb{R}^d$：词/双词频 (Word/bigram) 特征；依存句法树匹配 (Parse tree matches)
  * 应用多分类逻辑回归 (Multi-class logistic regression) 模型
* 神经网络方法：
  * 问题形式化
  * 输入：上下文 $C = c_1, c_2, \dots, c_N$，问题 $Q = q_1, q_2, \dots, q_M$
  * 输出：答案在上下文中的起止位置 $1 \le \text{start} \le \text{end} \le N$
  * 典型长度：$N \approx 100$, $M \approx 15$

> **[学习注释：传统抽取式阅读理解（MRC）的边界]**
> * **输入输出规则**：输入为特定的单篇上下文 $C$ 和问题 $Q$。无论是传统的特征匹配，还是以 BERT 为代表的神经网络模型，其核心假设都是“答案必须是原文的连续片段”，其输出本质上是答案在原文中的**起止 Token 索引指针**（$\text{start} \le \text{end}$）。
> * **局限性**：(1) 答案无法超出原文词句进行改写或跨文档概括；(2) 极度受限于上下文长度 $N$（当时模型窗口一般仅为 512 tokens），无法适应大规模知识检索。

## 页面 12: 开放域问答 (Open-domain Question Answering)

* 与阅读理解不同，我们不假设给定了文章。
* 相反，我们只能访问一个大型的文档库（例如维基百科）。我们不知道答案位于何处，目标是针对任何开放域问题返回答案。
* 这极具挑战性，也是一个更实用的问题！
* 相比之下，闭域问答系统（Closed-domain systems）处理特定领域（如医学、技术支持）下的问题。

> **[学习注释：开放域问答的解法转换与输出演进]**
> * **解法转换**：不假设给定文章，面对海量文档库，流程必须转变为**“先检索、后阅读”**，这奠定了现代 RAG 的物理雏形。
> * **输出演进**：
>   1. **早期抽取式**（如 DrQA 框架）：阅读器去检索出来的文档里“直接抠出原词片段”输出。
>   2. **现代生成式**（RAG 时代）：检索出的文档作为外部参考信息与问题拼接成 Prompt，由生成式大语言模型（LLM）“自主阅读并总结生成”自然语言回答。

## 页面 15: 检索器-阅读器 (Retriever-Reader) 框架

* 输入：大规模文档集合 $\mathcal{D} = \{D_1, D_2, \dots, D_N\}$ 以及问题 $Q$
* 输出：答案字符串 $A$（这本质上可以转化为一个阅读理解问题！）
* 流程：
  * 检索器：$f(\mathcal{D}, Q) \longrightarrow P_1, \dots, P_K$（其中 $K$ 是预先定义的，例如 100）
  * 阅读器：$g(Q, \{P_1, \dots, P_K\}) \longrightarrow A$
* 传统检索器 = 标准 TF-IDF 信息检索稀疏模型（固定模块）
* 传统阅读器 = 神经阅读理解模型（可以在 SQuAD 和其他远程监督问答数据集上训练，或者是零样本大语言模型，如 ChatGPT 等）

## 页面 17: 不同类型的检索器

我们应该如何为我们的检索系统检索相关的段落？
* 词语重合度 (BM25)
* 向量检索 (DPR, 句子向量 Sentence vectors)
* 其它神经系统 (ColBERT)

> **[学习注释：稀疏检索 vs 稠密检索的本质区别与向量化]**
> * **字面匹配（稀疏检索，如 BM25）**：基于词频统计判断字词是否重合。硬伤在于无法跨越“词汇鸿沟（Vocabulary Mismatch）”（例如搜“小狗”无法召回仅含“汪星人”或“犬科动物”的文章）。
> * **语义匹配（稠密检索，如 DPR）**：将文本投射为高维空间中的连续向量，衡量语义相似度，能有效捕捉同义近义关系。
> * **多 Token 句子的向量映射方式**：对于包含多个 Token 的 Query，通常通过三种方式变为单个固定维度向量：(1) **`[CLS]` Token 向量**（BERT 最顶层特殊占位符，通过自注意力机制凝聚全局语义）；(2) **平均池化（Mean Pooling）**（在序列维度求均值）；(3) **最大池化（Max Pooling）**（在序列维度取最大特征值）。

## 页面 18: 快速与慢速检索器

* 最快：在预计算好的向量上计算相似度（或词语重合度）
* 最慢：使用语言模型实时计算相似度
* 其他混合方式（如预计算“文档索引”），例如在 ColBERT 中

> **[学习注释：双塔极速检索 vs 单塔深度重排的物理设计差异]**
> * **双塔架构（Bi-Encoder，最快）**：Query 和 Doc 独立编码，Doc 的向量可以离线预计算并存入向量数据库，在线仅需计算 Query 向量并极速做近邻搜索（点积/余弦相似度），实现毫秒级响应。
> * **单塔架构（Cross-Encoder，最慢且最准）**：Query 和 Doc 拼接为 `[CLS] Query [SEP] Doc` 一同输入模型，每个字在每层进行 Self-Attention 交叉。由于无法预计算 Doc，必须在线实时两两配对跑前向传播，计算极其昂贵。
> * **为什么不把 Doc 放在前面以利用 KV Cache？**：
>   1. **架构限制**：传统 Cross-Encoder 是 Encoder-only（双向注意力，Attention Mask 为全 1）。前面的 Token 必须能看到后面的 Token。一旦后面的 Query 改变，前面 Doc 的隐状态和 KV Cache 立即作废，无法复用。
>   2. **精度权衡**：在单向自回归（Decoder-only）大模型中，若 Doc 在前、Query 在后，虽然可利用 Prompt Caching 节省计算量，但 Doc 在前向传播时看不到后面的 Query，属于“盲读”；而 Query 在前、Doc 在后，Doc 能“带着问题去阅读文章”，虽然牺牲了缓存，但语义召回精度显著更高。

## 页面 20: 我们可以训练检索器！密集通道检索 (DPR)

* 我们可以直接使用问答对来训练检索器！
* 可训练检索器（使用 BERT）的表现大幅优于传统的信息检索（IR）模型。
* Karpukhin et al., 2020. Dense Passage Retrieval for Open-Domain Question Answering

> **[学习注释：DPR 可训练检索器的训练本质与输入输出澄清]**
> * **“训练”的代数本质**：训练的不是数据库中已编码好的静态向量本身，而是**训练双塔编码器模型（Query Encoder 和 Doc Encoder）的神经网络权重**。训练利用问答对进行对比学习，让模型学会一种“能将问答语义对齐并投射到高维空间”的参数映射规则。
> * **澄清一：文档单向量表征（DPR 核心）**：在 DPR 中，一整篇文档/段落（而非每一个 token）经过编码后会被压缩表示为**唯一的一个固定维度向量（如 768 维）**。在线检索是“问题向量”与“文档单向量”的内积计算，从而彻底规避了逐 token 匹配的庞大计算开销。
> * **澄清二：训练的输入输出与负采样**：训练时模型的输入并非整个知识库，而是以批次（Batch）为单位的 `(问题 Q, 正文档 D+, 若干负文档 D-)`。各文档独立通过模型计算向量（互不占上下文，不会撑爆），并在损失函数层进行对比拉伸，以保证单篇文档对特定提问的检索匹配度。

## 页面 24: 实践中：语言模型无法有效利用过多文档

* 检索器性能（黄色曲线）缓慢上升至 90% 的召回率。
* RAG 性能（其他曲线）饱和得非常快 —— 在 10 到 20 篇文档之后就达到了上限。

> **[学习注释：RAG 评估指标中精确率与召回率的基准定义]**
> * **召回率 (Recall)**：$\frac{\text{被检索出来的相关文档数}}{\text{库中所有真正相关的文档数}}$。表示“网撒得有多宽”。随着检索文档上限 $K$ 增大，召回率缓慢上升至 90%。
> * **精确率 (Precision)**：$\frac{\text{被检索出来的相关文档数}}{\text{被检索出来的所有文档数}}$。表示“捞回来的信息纯度”。$K$ 变大导致大量无用垃圾文档被一并检索出来，精确率骤降，致使大模型注意力分散并产生幻觉，限制了最终的 RAG 性能。

## 页面 26: RARR：使用大语言模型研究和修改大语言模型的言论

[Guo+ 2023]
* 使用问答机制来检查信息源与生成回答之间的一致性。
* 使用语言模型为每一个内容项生成引用。
* 通过检测文本与引用之间的冲突来进行修改，并在必要时运行编辑模型修改文本。
* 选择证据片段来生成属性报告。

> **[学习注释：RARR 事后纠错机制与“引用生成”的本质]**
> * **何时发生？**：发生在**推理阶段（测试期）**，是无需重新训练模型的 Pipeline 事实纠错机制。由一个专门的 LLM 自动将生成回答拆解出若干微型问题，去网络库检索证据并对比一致性，发现冲突时调用编辑模型进行修改。
> * **什么是“生成引用”？**：指大模型在写出事实句时，**动态决策在何处打上引用角标（如 `[1]`）以及从长篇文档中抽取/生成一句话作为微型证据的过程**，而非简单贴出源文档的 URL，这也是其可能产生“引用幻觉”的代数来源。

## 页面 28: 大语言模型引用与幻觉 (续)

* 模型的输出易于阅读，且对评估人员显得有用（在 1-5 分的量表上）。
* 但引用的精确率 (precision) 和召回率 (recall) 都比较低……

> **[学习注释：引用幻觉的评估与“裁判与运动员解耦”权衡]**
> * **精确率与召回率的度量**：(1) **Precision**：模型打上角标的所有生成句中，确实能被引用文档支持的句子的比例；(2) **Recall**：模型写出的所有事实句中，打上了正确引用角标的句子的比例。
> * **如何评估“相关/支持”？**：判定“文档是否支持生成句”是一个基于逻辑蕴含的 **0/1 标签**，一般通过特化的 NLI 推理分类器（如 DeBERTa-v3-MNLI）或大模型裁判（LLM-as-a-judge）实现。
> * **核心思考：为什么不直接让“裁判模型”来生成回答？**
>   1. **任务难度不对等**：判定一个已知步骤的逻辑对错（二分类）比凭空撰写回答的开销和难度要低得多。
>   2. **特化偏科**：裁判常常是只懂逻辑分类而完全不会日常对话的微型特化模型（如 NLI 模型）。
>   3. **规避自我偏见（Self-Correction Bias）**：大模型生成时存在盲目自信，必须由另一个独立的模型（裁判）对照背景从零审核。
>   4. **商业算力考量**：可用轻量便宜的小模型做前台生成，仅在关键事实点调用一次昂贵的极大模型（如 GPT-4）做 0/1 审核，以极限节省 API 成本。

## 页面 34: 为什么推理对智能体有用？

从“观察”直接映射到“行动”可能是非常困难的。
* 普通模型：
  * 观察 $t$：看到柜子和桌子…… $\to$ 行动 $t$：向右转
  * 观察 $t+1$ $\to$ 行动 $t+1$：打开柜子
* 结合推理的模型（根据推理决策行动）：
  * “这道菜应该有咸味，但盐用完了，所以我应该找酱油代替。它在我右边的柜子里……”
  * 推理使得行动更具概括性 (Generalization) 和对齐性 (Alignment)。

## 页面 35: 无行动的推理 (Reasoning without acting)

* 问题：除了 Apple Remote 之外，还有什么其他设备可以控制 Apple Remote 最初设计用来交互的程序？
* 仅推理 (Reason Only) 方式：
  * 思考：让我们一步一步思考。Apple Remote 最初是设计用来与 Apple TV 交互的。Apple TV 可以由 iPhone、iPad 和 iPod Touch 控制。因此答案是 iPhone、iPad 和 iPod Touch。
  * 答案：iPhone, iPad, iPod Touch

## 页面 36: 结合行动的推理 (Reasoning with acting) —— ReAct

[Yao et al., 2022]
* 问题：除了 Apple Remote 之外，还有什么其他设备可以控制 Apple Remote 最初设计用来交互的程序？
* **ReAct 运行轨迹 (Reason + Act)**：
  * **思考 1**：我需要搜索 Apple Remote 并找到它最初设计交互的程序。
  * **行动 1**：`Search[Apple Remote]`
  * **观察 1**：Apple Remote 是苹果公司于 2005 年 10 月推出的一款遥控器……最初设计用于控制 Front Row 媒体中心程序……
  * **思考 2**：Apple Remote 最初设计用于控制 Front Row 媒体中心程序。接下来我需要搜索 Front Row，找到还有什么其他设备可以控制它。
  * **行动 2**：`Search[Front Row]`
  * **观察 2**：未找到 [Front Row]。相似词：['Front Row Seat to Earth', 'Front Row (software)', ...]
  * **思考 3**：未找到 Front Row。我需要搜索 Front Row (software)。
  * **行动 3**：`Search[Front Row (software)]`
  * **观察 3**：Front Row 是一款已停用的媒体中心软件……它可以通过 Apple Remote 或键盘功能键来控制。
  * **思考 4**：Front Row (software) 由 Apple Remote 或键盘功能键控制。所以答案是键盘功能键。
  * **行动 4**：`Finish[keyboard function keys]`

## 页面 38: 自我一致性 (Self-Consistency)

[Wang et al., 2023]
* 使用思维链提示（CoT prompting）引导语言模型。
* 生成一组多样化的推理路径。
* 通过在最终答案集中选择最一致（出现次数最多）的答案来进行聚合。

> **[学习注释：自我一致性 (Self-Consistency) 的底层控制与边界澄清]**
> * **推理与回答的自回归控制**：在大模型底层中，推理过程（CoT）与回答**并非**物理割裂的两个步骤，而是在**同一次自回归生成中先后输出的**。模型先输出思考过程，再通过生成一个**特殊的分隔符 Token**（如换行或特定的标签如 `</think>`），将整个推理链作为记忆上下文，继续自回归续写生成最终答案。
> * **多路径并行与事后收卷机制**：
>   * 算法并**没有**在中途阻断各进程的生成。真实流程是：通过设定大于 0 的采样温度，让 $n$ 个实例**独立且完整地跑完各自的“推理+回答”全流程**。
>   * 结束后，由外部运行的 Python 脚本充当“计票员”，用正则表达式从这 $n$ 份答卷末尾**静态抽取**出最终选项或数值进行频次统计，将得票数最多的答案（或产生该答案的某一条完整路径）返回给用户。
> * **适用场景与现实日常场景的边界差异**：
>   * **课件学术场景**：仅适用于有**“确定性唯一最终答案”**的硬推理任务（如数学计算题、逻辑选择题、代码实际运行结果等）。这些任务的演算过程虽异，但正确答案必定收敛。
>   * **日常通用对话场景**：面对开放式长文本（如“写一封信”），各实例输出的文本字面完全不同，无法通过脚本字面频次进行投票。
>   * **现实中的替代/演进方案**：在开放式复杂场景中，简单的字面统计往往被以下方案替代：(1) **大模型裁判融合（LLM Fusion）**：让另一个更强的 LLM 读入多个初稿进行要点提取与总结重写；(2) **语义聚类投票（Semantic Clustering）**：利用 Embedding 向量距离对语义相似的短语进行聚类并计票。

## 页面 39: Reflexion：通过自然语言反馈强化智能体

[Shinn et al., 2023]
* Reflexion 智能体对任务反馈信号进行口头/文本形式的反思，然后维护他们自己的反思文本，以做出更好的决策。

> **[学习注释：Reflexion 反思文本的动态维护与提示机制]**
> * **独立模块维护**：反思文本是被单独的外部记忆区（Memory）维护的，而非写入模型底层的参数。
> * **多轮反思的维护方式**：当任务尝试失败时，模型根据上一轮的完整失败轨迹生成一段总结性教训（如“之前使用了递归，应当改用循环”），并**直接追加（Append）**到缓存中。在开始新一轮尝试时，系统会将缓存中的这批历史失败反思完整拼接到 Prompts 的前端作为“自我提示（Self-Hints）”，从而构成一个滑动窗口式的历史反思链，避免了重复犯错。

## 页面 48: 情节记忆 (Episodic Memory)

* **写操作**：仅追加（append-only）的事件流。
* **读操作**：基于启发式得分（相关性、新颖性、重要性）的检索。

> **[学习注释：情节记忆中启发式得分的三维代数澄清（基于 Park et al., 2023）]**
> * **重要澄清：启发式得分不是由三个指标直接拼成向量去算相似度**。其真实代数计算是将三个维度分别计算为**标量（数值）**后在外部进行**加权求和**得出最终得分。
> * **三维度的具体计算与维护机制**：
>   1. **新颖性（Recency, $S_{rec}$）**：动态计算时差 $\Delta t$（距今游戏小时数），采用指数衰减函数 $0.99^{\Delta t}$。
>   2. **重要性（Importance, $S_{imp}$）**：在新记忆写入时，调用一次 LLM 对事件对个体的影响度进行离线评级（1-10分），所得数值作为静态元数据字段永久保存在数据库中，检索时直接读取。
>   3. **语义相关性（Relevance, $S_{rel}$）**：将当前查询问题 $Q$ 和单条情节记忆文本 $M_i$ 分别用 Embedding 模型映射为**高维稠密语义向量**（如 768 维），计算二者的余弦相似度得到标量分值。

---

## 页面 49: 语义记忆 (Semantic Memory)

* **写操作**：大语言模型在事件之上进行推理与概括（提炼成高层次的反思与信念）。
* **读操作**：根据相似度进行检索。

> **[学习注释：语义记忆的获取与向量相似度检索]**
> * **写入与提炼（写操作）**：当情节记忆积累到一定深度时，触发反思过程。大模型阅读这些记忆，提炼生成高层次的反思文本（例如：“John 比较重视友情，习惯和同事打交道”），这代表了高级的性格和信念系统。
> * **向量化与读操作**：同样通过**高维稠密文本 Embedding 编码模型**，将反思文本转为高维稠密特征向量 $\vec{s}$（存入向量数据库）。检索时计算当前提问向量 $\vec{q}$ 与其之间的余弦相似度，以获取能够维持智能体宏观性格连续性的大层次反思信息。

## 页面 54: ToolkenGPT

[Hao et al., 2024]
* ToolkenGPT 将每个工具表示为一个 Token（即 "toolken"）并为其学习向量嵌入，使得调用工具就像生成一个普通的单词 Token 一样。
* 一旦触发了 toolken，大语言模型就会被提示为该工具补全执行参数。

> **[学习注释：ToolkenGPT 中断-参数补全-恢复的状态机运行机制]**
> * **生成中途阻断与状态机切换**：触发 toolken 并为工具补全参数的过程中，确实存在**文本生成的中途阻断与状态切换**。
> * **具体流程**：(1) 模型顺序自回归生成，一旦预测出的下一个 Token 为特殊的工具 Token（如 `[TOOL:Calculator]`），推理引擎**强行暂停**生成；(2) 外部控制流接管，在 Prompt 尾部添加引导词并限制模型词表只能输出数字和符号；(3) 模型在此约束下继续生成参数（如 `(2+3)`），右括号出现时触发**第二次中断**；(4) 外部代码执行计算得出结果 `5` 并拼接回 Prompt 尾部，解除词表限制，大模型重新开始前向传播以恢复常规生成。
> * **现代工程中的应用**：在 Function Calling 落地中，这被称为 **Stop Sequences（停止词拦截）**，当模型输出特殊的结构化标签尾部（如 `</tool_call>`）时，自动中止前向传播，待外部 API 运行结果拼回 Context 后再次拉起模型。

## 页面 56: Toolformer：自监督学习与 API 过滤机制

* 对于输入 $\mathbf{x}$，采样一个位置 $i$ 和相应的 API 调用候选 $c_i^1, c_i^2, \dots c_i^k$。
* 随后执行这些 API 调用，并过滤掉所有无法降低后续 Token 预测损失 $L_i$ 的调用。
* 将所有保留下来的 API 调用与原始文本交织，形成新的训练文本 $\mathbf{x}^*$。

> **[学习注释：Toolformer 数据构造训练本质与后续损失下降机制]**
> * **训练本质（自监督 SFT，而非 RLHF）**：这是一种“自举生成数据 + 过滤提炼”的数据生成方案。最终模型直接在这批被过滤干净、交织着合理 API 调用和结果的训练数据上进行**常规自回归最大似然微调（SFT）**，从而让模型学会像“复读机”一样在合适的位置输出 API 标签。
> * **后续预测损失下降的代数本质**：
>   * 损失（Loss）并非针对某个单独的“关键词”，而是针对 API 标签插入点位置 $i$ 之后、直到句子结束的一整段**后续目标文本序列 $\mathbf{y} = x_i, \dots, x_j$ 的累加平均交叉熵损失**。
>   * 为了公平比对，系统在以下三种配置中**预测的目标序列 $\mathbf{y}$ 完全一致**，仅仅改变**输入给模型的上文 Context（条件概率的条件）**：
>     1. **$L^+$ (带 API 结果)**：输入包含 API 动作与返回值（如 `[Calc(167*0.7) -> 1170000]`），预测 $\mathbf{y}$。因答案存在于上文中，模型预测 $x_i = 1170000$ 的概率趋近于 1，使整个后续序列的累加负对数似然损失 $L^+$ 极大下降。
>     2. **$L^-$ (无 API)**：输入完全无 API。模型必须盲猜数值，预测损失 $L^-$ 维持在高位。
>     3. **$L^{empty}$ (有调用但无结果)**：输入包含调用但无返回值。损失为 $L^{empty}$。
>   * **过滤不等式**：只有当 $\min(L^-, L^{empty}) - L^+ > \tau$（$\tau$ 为预设正阈值）时，才判定该 API 调用真正对预测后续文本起到了关键作用，予以保留，否则一律过滤清除。

* 存在多种有效的求解路径
* 无法通过简单的脚本计算评估指标，需要人类裁判
* 对任务成功率之外的多维度评估
评估方式：通过基准测试 (Benchmarks)；通过大语言模型/多模态模型评判；通过众包评估。

最简单的情况下，一个 AI 编程智能体就是一个大循环。给出一个任务，例如“为我创建一个网页应用”，我们启动以下循环：
1. 大语言模型提出一个行动 (Action)。

3. 将执行结果输出告诉大语言模型。
4. 重复步骤 2-4！
