## 页面 8: 语言模型是如何看待文本的？Token 与词表 (Vocabulary)

对于语言模型而言：
* 语言的基本单元是 **Token (词元/标记)**。
* **分词 (Tokenization)** 是将连续文本切分为 Token 序列的过程。
* **分词器 (Tokenizer)** 在原始文本与大语言模型（LM）学习的 Token ID 编码序列之间进行转换。
* **词表 (Vocabulary)** 是所有已知 Token 的集合。
  * 例如：`We looked at the Milky Way.` $\to$ 分词器映射 $\to$ `[2167, 10802, 540, 290, 10282, 5781, 0]`

## 页面 9: 为什么我们需要分词 (Tokenization)？

* **本质原因**：语言模型（如 Transformer）无法直接读取和理解原始的字符串。我们必须通过分词，将字符/文本片段映射为对应的离散 Token ID，然后通过查表转化为连续空间的特征向量（Embedding 嵌入）。

* 分词过程影响了语言模型学习和处理文本的方式，这一机制甚至在模型的权重训练开始之前就被完全确定了。

## 页面 16: 分词对大语言模型运行效率 (序列长度与参数量) 的影响

* 较小的 Token 单元（如字符级）会产生极长的序列长度，导致 Attention 二次方开销爆炸。
* 较大的 Token 单元（如单词级）会产生过于庞大的 Embedding 矩阵，浪费模型的参数空间。

* 词表（Vocabulary）大小直接决定了模型的输入词表嵌入矩阵（Input Embedding Matrix）以及输出概率预测 Softmax 层的大小。

## 页面 18: 单词级分词 (Word Tokenization) 及其优缺点

* **定义**：将空格分隔的单词和标点符号作为 Token。词表通常被截断为语料库中出现频次最高的前 $V$ 个单词。
* **优势 (Pros)**：
  * 具有非常清晰的语义学含义（Semantically meaningful）。
  * 一个 Embedding 向量几乎直接对应一个可解释的语义单元。

---

## 页面 19: 单词级分词的局限性：Zipf 定律与动态演变的语言

* **劣势 (Cons)**：
  * **词表过度臃肿**：真实的语言中存在海量的单词。
  * **长尾分布**：齐普夫定律 (Zipf’s law) 指出，一个单词在语料中的出现频次与其频次排名成反比。存在极多极少出现的低频词。
  * **语言时刻处于演变之中**：例如《韦氏大学词典》在第 12 版中一口气新增了 5,000 个新词（如流行语 `rizz`），传统的固定单词词表完全无法应对新词。

---

## 页面 20: 单词级分词的局限性：未登录词 (OOV) 与 UNK 占位符

* 面对**未登录词 (Out-Of-Vocabulary, OOV)** 难题的常规做法：
  * 做法 1：利用复杂的正则表达式或人工规则进行拼写纠错或时态规整。
  * 做法 2：引入一个统一的未知词占位符 `<UNK>`。
  * ⚠️ **后果**：这会导致大量稍微偏门的词汇被强行粗暴地映射为同一个无意义的 `<UNK>` 向量，损失了全部信息。

---

## 页面 21: 字符/字节级分词 (Character/Byte Tokenization) (无分词器方案)

* **定义**：将文本中的单个字符或字节作为 Token 单元。
* **字符 vs 字节**：
  * 例如表情符号 `😀` 占 1 个字符，但占 4 个 UTF-8 字节。汉字 `地` 占 1 个字符，但占 3 个 UTF-8 字节。
  * 代表模型：CharBERT, CANINE, Charformer, ByT5。
* **优势 (Pros)**：
  * 词表极小（仅需容纳各种字符或 256 个字节）。
  * 彻底消除了未登录词（No OOV!），对任何输入文本具有 100% 的覆盖率。
  * 能够直接洞察单词内部的拼写字母特征。
* **劣势 (Cons)**：
  * 生成的序列极其漫长（Attention 计算和生成开销极大）。
  * 神经网络可能更难从单字节/单字符起步去拟合复杂的深层抽象语义（虽然仍有争论）。

---

## 页面 22: 介于单词与字符之间：子词分词 (Subword Tokenization)

* **核心直觉**：利用数据驱动的算法，根据文本中相邻字符片段的统计频次，自动生成最合理的词表大小与内容。
* 它在单词（语义表征好但易出现 OOV）与字符（无 OOV 但序列太长）之间取得了完美的黄金平衡。
* 示例：
  `We’d sat back on the grass, and time flew by as we looked at the Milky Way.`
  通过 ChatGPT 分词器切分时，频繁使用的 `looked` 可能会被切分为 `look` 与 `ed`，既保留了语义基础，又大幅降低了词表冗余度。

---

## 页面 23: 常见的子词分词算法：BPE, WordPiece 与 Unigram LM

* **字节对编码 (Byte Pair Encoding, BPE)** [Sennrich et al., 2016]：
  * 从底层的单个字节/字符集起步，通过在语料库上统计，迭代合并出现频次最高的相邻 Token 对。
* **WordPiece** [Wu et al., 2016]：
  * 与 BPE 类似，但其合并条件不是频次，而是评估合并后是否能最大化整个数据集的似然概率。
* **Unigram 语言模型 (ULM)** [Kudo, 2018]：
  * 采用“做减法”逻辑。先用所有可能的子串构建一个极其庞大的初始词表，然后根据对训练似然度的贡献，逐步剔除低效 Token 直至达到设定的词表大小。
* 本节课我们将重点剖析使用最广的 **BPE 算法**。

## 页面 25: BPE 子词分词算法：训练步骤

BPE 词表构建的核心训练算法：
* **前置输入**：训练语料库 $\mathcal{D}$，期望的最终词表大小 $N$。
* **核心步骤**：
  1. 通过空格对语料库进行基础的预切分（预分词）。
  2. 初始化词表 $V$ 为语料库 $\mathcal{D}$ 中出现的所有基础字节/字符。
  3. 将语料库 $\mathcal{D}$ 中的所有单词拆写为字符/字节序列。
  4. 开启循环，当当前词表大小 $|V| < N$ 时：
     * 统计语料中所有相邻双元 Token 对（Bigrams）的出现次数。
     * 将出现频次最高的那一组 Token 对 $(v_i, v_j)$ 合并为一个全新的 Token $v_{new} = v_i v_j$。
     * 将合并后的 $v_{new}$ 塞入词表 $V$。
     * 在语料库 $\mathcal{D}$ 中将所有的 $v_i v_j$ 序列全部替换为单 Token $v_{new}$。

## 页面 54: BPE 推理阶段分词步骤：应用合并规则

在测试或推理阶段，对于任何新输入的文本，分词器首先将其拆分为原始的字节/字符流，然后**严格按照训练过程中记录的合并规则列表的顺序**执行合并操作：
* **输入单词**：`_ p i e r`
* **合并规则 1**：`_ + p -> _p` $\to$ 语料变为 `_p i e r`
* **合并规则 3**：`e + r -> er` $\to$ 语料变为 `_p i er`
* **合并规则 5**：`_p + i -> _pi` $\to$ 语料变为 `_pi er`
* 合并结束，输出 2 个 Token。

## 页面 56: 超越子词分词：SentencePiece 与超词分词 (SuperBPE)

* **SentencePiece** [Kudo & Richardson, 2018]：
  * 它是一个开源的分词器库（而非独立算法），实现了 BPE 和 Unigram LM 算法。
  * **核心创新**：将空格当作普通的可见基础字符（例如 `_`）放入词表中直接训练，消除了对特定语种空格规则的依赖。被 LLaMA, T5, Gemma 等多语言模型广泛使用。
* **超词分词 (SuperBPE)** [Liu et al., 2025]：
  * 一种前置的“超词学习课程”。打破原有的空格边界约束，直接让常用短语或短句合并为一整个“超词（Superword）”Token，显著缩短了生成序列，节省了推理算力。

## 页面 57: 子词分词是一劳永逸的终极方案吗？

* 虽然 BPE 作为一种无损的高效压缩算法已经在业界成为事实标准，完美解决了 OOV 问题，但它依然不是完美无瑕的，还存在很多悬而未决的漏洞。

## 页面 58: 案例研究 1：草莓里的“r”有多少个？拼写困境

🍓 **经典的 Strawberry 难题**：
* 为什么大模型连“strawberry”里有几个“r”都数不清？
* 根源在于分词：
  * GPT-2 将其切分为 `["str", "aw", "berry"]`
  * GPT-4o 将其直接切分为单个 Token `["strawberry"]`（整个单词在模型眼里是一个不透明的黑盒单位）
* 无论哪种切分，大模型的自回归编码都无法直接读取底层的单个字符 `r`，只能进行脑补！

## 页面 59: 大语言模型在拼写、倒序字符串及 typo 鲁棒性上的缺陷

* **单词拼写**：模型必须费力地在隐藏表示中将一个封装好的 Token 反解（Reverse-engineer）为字符表示。
* **倒序输出字符串**：要求字符级的逆向寻址，而分词器从不提供这种细粒度通路 [Huang et al., 2023]。
* **对错别字（Typos）脆弱**：在单词中稍微改错一个字母，会完全打乱 BPE 的相邻频次合并路径，导致生成截然不同的全新 Token ID 序列，让模型产生逻辑混乱。

---

## 页面 60: 案例研究 2：故障 Token (Glitch Tokens)

* **定义**：指那些进入了分词器词表，但在大模型实际的语料预训练阶段极少甚至从未露过面的罕见 Token。
* 它们对应在模型底层的 Embedding 权重在训练期间从未得到过更新，依然处于随机初始化的混乱状态，一旦被唤醒就会引发模型的反常行为。

---

## 页面 61: 故障 Token 的成因与经典案例：SolidGoldMagikarp

* **典型代表**：`SolidGoldMagikarp` (一个 Reddit 用户名)。
  * 在训练分词器时，它因在特定网页数据中高频出现而强行塞入词表。但在训练大模型的语料中却彻底消失了。
  * 当用户命令 GPT-3 重复该 Token 时，模型会发生崩溃、胡言乱语或吐出完全无关的词（如“distribute”）。
* **Magikarp 探针 (Land & Bartolo, 2024)**：发现这类故障 Token 在 LLaMA, Qwen 等大模型中普遍存在。这不仅浪费了宝贵的词表位置，更构成了针对大模型的潜在对抗性安全漏洞。
* **铁律**：千万不要让训练分词器的数据与训练大模型的数据发生严重脱节。

## 页面 63: 为什么要关注多语言性？世界语言生态

* 全球记载的语言有 7,000 多种！
* 全球约有 20% 的人口会说英语，但原生母语是英语的人仅占 5%。
* 现实世界的需求完全是多语言的（翻译、跨国检索、语种混杂）。
* **价值对齐**：如果自然语言处理工具只能在英语上表现优异，我们就是在开发一项排斥世界上绝大多数人口的偏见技术。

## 页面 64: 互联网数据中的多语言失衡：高资源 vs 低资源语言

* 尽管世界语言呈现多样化，但作为模型训练绝对主力的数据源 Common Crawl 中，**有 40% - 45% 的数据都是纯英文！**
* **高资源语言 (High-resource)**：如英语、法语，拥有海量的数字化文本以及丰富的标注集。
* **低资源语言 (Low-resource)**：如 Amharic, Yoruba, 数字化文本极度稀缺，在 Common Crawl 中占比甚至低于 0.01%，训练极为艰难。

## 页面 66: 多语言语言模型 (Multilingual LM) 的设计与历史演进

* **核心原理**：多语言模型与单语言模型在神经网络架构（相同 Transformer）上完全一致。唯一的区别在于：它的分词器和模型训练使用了混合了多个语种的语料库。
* 演进脉络：mBERT (2018) $\to$ XLM-R (2020) $\to$ mT5 (2021) $\to$ BLOOM (2022) $\to$ GPT-4 / Llama 等通用多模态对齐大模型。

---

## 页面 67: 跨语言迁移 (Cross-lingual Transfer) 带来的零样本推理能力

* **跨语言迁移**：多语言模型共享底层的表征空间。模型即使仅在英语（English-only）的有监督情感分类数据上进行了微调，也能在完全没有任何对应语言微调的前提下，直接泛化去处理法语、中文或德语的零样本情感分类任务。

---

## 页面 68: 词表大小与重合度对跨语言迁移的影响

* **重合度红利**：不同语种之间重合的子词 Token 能够极大地促进跨语言迁移的表现。甚至不同语义的相同字型（“false friends”）也有助于在隐层特征空间对齐跨语言的 Embedding。
* 词表的分配往往是约束性能的瓶颈，XLM-V 尝试将词表扩大到 1M 规模以改善长尾语种的覆盖率，但带来了极高的参数量代价。

---

## 页面 69: 多语言魔咒 (Curse of Multilinguality)：模型参数容量瓶颈

* 跨语言迁移并非银弹。
* **多语言魔咒**：在模型整体参数容量固定的前提下，引入的语种越多，跨语言迁移的表现反而会开始下降。
* **根源**：因为模型参数是有限的，更多语种被迫去共享和瓜分有限的特征空间。当语种过多时，原本表现极佳的高资源语言（英语、法语）的性能会显著下滑。

## 页面 70: 英语之外的分词差距：同一句话的膨胀比率

再次凸显英语之外的分词低效性：用不同语言表达相同含义时，英语仅需 21 个 Token，而法语需 27 个，泰语甚至飙升至 36 个。

## 页面 71: 分词机制给非英语用户带来的财务与技术不平等

* **商业 API 计费惩罚**：OpenAI 等商业大模型按 Token 计费。非英语用户支付高出多倍的费用，仅仅是为了传输相同语义的文本。
* **技术性能受损**：子词生育率 (Subword fertility，即每个单词被切分出的平均 Token 数量) 越高，下游任务的准确度就越低。非英语用户被迫忍受更短的上下文窗口以及更差的逻辑表现。

## 页面 73: 提高字节级模型处理效率：MrT5 动态删除门机制 (Kallini et al., 2025b)

* **MrT5 创新机制**：为了克服字节级模型处理超长序列时的计算瓶颈，MrT5 引入了一个**可学习的删除门 (Delete Gate)**。
* 它可以对不太重要或冗余的单字节进行动态舍弃，大幅缩减了中间的序列表示长度，使字节模型实现多倍的计算提速。
